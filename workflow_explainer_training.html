AI 協作簡報不是一次生成，而是一條可治理的工作流

這次案例最值得團隊內訓的地方，不是最後那份簡報長什麼樣，而是它為什麼能穩定產生那個結果。 真正的關鍵不在模型突然變強，而在於 source、template、design contract、逐頁執行、品質門檻與人工回修被串成同一條 workflow。

這份分享想談的，不是單純哪一個 AI 工具比較強，而是當 AI 真正進入開發流程後，我們該如何建立可治理的協作方式。

      Responsibility Boundary

      四個角色各自解決什麼問題

      1. Source Layer

      內容來源管理

      • 定義 deck 的唯一內容來源。
      • 避免 AI 一邊生內容、一邊改內容方向。
      • 讓後續 review 能區分內容問題與設計問題。
      2. Strategist

      把需求翻成設計合約

      • 決定頁數、節奏、受眾、語氣、視覺系統。
      • 把 reference template 轉成可執行的 page mapping。
      • 輸出 design_spec.md 與 spec_lock.md。
      3. Executor

      逐頁把合約翻成畫面

      • 依照 spec_lock 一頁一頁寫進 SVG。
      • 保留 deck 一致性，同時處理不同頁型節奏。
      • 不能脫離 contract 自由發揮新視覺語法。
      4. QA / Annotation

      把可用結果收斂成可信結果

      • quality gate 擋下格式與規格問題。
      • live preview 標註處理主觀視覺落差。
      • 將「合格」進一步拉近到「符合期望」。
      Why Template Fidelity Was High

      為什麼這次生成結果能這麼貼近 DataEco layout

      Template 先被具體化

      不是抽象地說「像 DataEco」，而是先把 reference deck staged 到 templates/dataeco_reference。 這讓 cover、quote-photo、ending 等頁型都變成具名可引用的版型語法。

      Spec Lock 負責防止 drift

      顏色、字體、page rhythm、page layout mapping 都被寫進 spec_lock.md。 Executor 每頁重讀，因此 deck 不會在中段逐漸偏離 template 系統。

      標註迴圈把主觀偏差修回來

      即使初版已經合格，封面、第二頁與結尾頁仍透過 annotation 回修， 把原本偏暗、偏空或不夠一致的頁面重新拉回白底綠色 DataEco 語法。
